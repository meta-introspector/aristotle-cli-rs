# Arist Web Surface — architecture and project-mount procedure

The public web surface at **https://solana.solfunmeme.com/arist/** — what serves
it, how projects mount into it, and the procedure for adding a new one.

*Last updated: 2026-09-09*

## Topology

```
Browser
  → nginx :443 (solana.solfunmeme.com, Let's Encrypt, HTTP/2)
    → location /arist/ → proxy_pass http://127.0.0.1:8157
      → aristotle-web.service (node web/agent.js serve 8157, User=mdupont)
        → SPA: index.html + agent.js (ESM) + agent.wasm
        → /api/memory, /api/memory/records — paginated redacted records
        → /cross-reference, /diagonalize, /hesper — feature pages
        → serveStatic: STATIC_DIRS + PROJECT_DIRS under web/
```

- **Service**: `/etc/systemd/system/aristotle-web.service`, ~2.5–6 min startup
  (ingests ~195K records from 12 agent-harness connectors on boot)
- **Served root**: `~/projects/arist/d79d4cfd-1c60-40fc-ae16-bb0498953ec1/output-final_aristotle/web/`
  (itself a symlink into `/mnt/data1/time-2026/05-may/07/arist/...`)
- **agent.js**: `root` = dirname(agent.js)/..; static files read per-request —
  **no restart needed when content changes**

## Procedure: mount a new Aristotle project's site

1. **Symlink** the project's `www/` (or site dir) into the served web dir:
   ```bash
   ln -sfn /mnt/data1/aristotle-results/<uuid>_aristotle/output-final_aristotle/www \
           ~/projects/arist/d79d4cfd-1c60-40fc-ae16-bb0498953ec1/output-final_aristotle/web/<short-id>
   ```
2. **agent.js**: add `<short-id>` to both `STATIC_DIRS` and `PROJECT_DIRS`.
   - `PROJECT_DIRS` members serve `index.html` on the bare dir (SPA entry)
   - `STATIC_DIRS` members' subdirs fall through to the project's own assets
3. **Nav button**: add `<a href="/arist/<short-id>/">` to the main index.html
4. **Verify** direct (8157) and through nginx:
   ```bash
   curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8157/<short-id>/
   curl -s -o /dev/null -w '%{http_code}\n' https://solana.solfunmeme.com/arist/<short-id>/
   ```

## Gotcha (fixed 2026-09-09): ESM + require

`serveStatic` in agent.js used `require("fs").readFileSync` — but agent.js is an
**ES module**, where `require` is undefined. The resulting ReferenceError was
swallowed by the catch block → every static file 404'd. This bug existed since
`serveStatic` was first added (all static mounts were silently broken until
tested individually). Fix: use the already-imported `fssync`
(`const fssync = await import("node:fs")` at module top).

**Lesson**: when adding a mount, curl the asset subpaths, not just the bare dir —
the bare dir works via the SPA fallback even when serveStatic is broken.
